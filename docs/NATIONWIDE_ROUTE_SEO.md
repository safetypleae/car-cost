# 전국 지역 간 검색 SEO — 구현 기준

## 목표
- 사용자가 "지역에서 지역", "지역 지역 기름값", "지역 지역 톨비"처럼 검색할 때 도움이 되는 차비얼마 콘텐츠와 계산기로 연결한다.
- 전국 시·군·구의 **어떤 조합도** `/routes`에서 입력해 계산기로 이동할 수 있게 한다.
- 검색엔진에 노출되는 경로 상세 페이지는 실제로 검증된 고유 콘텐츠가 있는 경로만 발행한다.

## 현재 구현
1. `/routes`의 GET 폼은 임의의 출발지·도착지를 `/?from=...&to=...`로 전달한다. 추천 목록은 `src/data/regions.ts`의 17개 광역권 시·군·구 제안이며, 입력을 제한하지 않는다.
2. 메인 계산기는 두 지역의 텍스트를 미리 채운다. **장소 검색 API는 사용자가 입력창을 클릭할 때만** 호출된다. 실제 장소 선택 전에는 경로·유가 API 호출이 없다.
3. 기존 고유 콘텐츠가 있는 `/routes/[slug]` 페이지는 자연어 제목·설명과 해당 경로를 미리 채우는 계산기 링크를 제공한다.
4. 기존 `sitemap.ts`는 고유 경로 데이터에 있는 페이지만 포함한다. 검색어 조합별 동적 페이지, 자동 생성된 유사 콘텐츠 페이지는 발행하지 않는다.

## 추가 지역 경로 페이지의 발행 기준
- Google Search Console / 네이버 서치어드바이저에서 실제 유입 검색어와 수요를 확인한다.
- 출발·도착 지역에 대한 정확한 지명과 중복 없는 구간별 이동 정보를 검증한다.
- 거리·소요시간·톨비를 표기하려면 출처·기준일·차량/경로 가정이 있는 정적 스냅샷을 사용한다.
- 페이지 렌더링이나 크롤러 방문 때 네이버/카카오 경로 API를 호출하지 않는다.
- 유사한 지역 조합을 수천 개씩 자동으로 색인하지 않는다.
- 성과 확인 후 콘텐츠가 충분한 경로만 `route-guides`, `route-content`에 추가하고 sitemap에 반영한다.

## 검증
- PR GitHub Actions `Cloudflare build` 통과 확인: `tsc`, Next build, OpenNext build, Worker dry-run.
- 수동: `/routes`에서 임의의 두 지역 입력 → 홈 입력창 미리 채워짐 → 클릭하여 장소 선택 → 계산.
- 수동: 기존 경로 상세 페이지에서 계산 링크 → 두 지역 미리 채워짐.
- 수동: 페이지 방문만으로 `/api/places`, `/api/route` 요청이 발생하지 않는지 확인.
- PR은 검증 전 `main`에 병합하거나 Cloudflare 운영에 배포하지 않는다.
